## 1. 定位与触发

`package.json` description 原文：

> This is a 12306 ticket search server based on the Model Context Protocol (MCP).

README 原文补充：

> The server provides a simple API interface that allows users to search for 12306 tickets.

它没有 `SKILL.md` 和自然语言 description 触发器；MCP host 依据 server instructions 与 8 个 tool description 选用。server instructions 表明它用于车票、特定列车经停与车站信息，并要求信息不足时追问、尽量用 filter 缩短上下文。

8 个真实 tool（本地 MCP `tools/list` 也返回同一集合）：

1. `get-current-date`：上海时区日期，解析“明天/下周三”。
2. `get-stations-code-in-city`：中文城市 → 所有站名/`station_code`。
3. `get-station-code-of-citys`：一个或 `|` 分隔多个城市 → 代表站；公共 API 名有 `citys` 拼写错误。
4. `get-station-code-by-names`：具体中文站名 → code/name。
5. `get-station-by-telecode`：3 位 telecode → 完整车站信息。
6. `get-tickets`：直达余票、价格与筛选。
7. `get-interline-tickets`：中转余票（默认/最多取前 10 条一类分页结果）。
8. `get-train-route-stations`：车次在日期内的经停站与时刻。

典型触发意图来自 tool descriptions：车票/余票、高铁/动车过滤、某城市有哪些站、站码查询、指定中转、某车次经停站。

## 2. 输入、输出与数据结构

源码：`src/index.ts`（tool schema/流程）与 `src/types.ts`（上游/归一化类型）。

### station tools

- city station 输入 `city:string`；输出以 MCP `content[0].text` 承载 JSON 字符串数组 `[{station_code,station_name}]`。
- name/code tools 使用 `citys`、`stationNames`（支持 `|`）或 `stationTelecode`；完整 `StationData` 字段：`station_id/name/code/pinyin/short/index/code/city/r1/r2`。

### `get-tickets`

输入：

- 必需 `date` (`yyyy-MM-dd`)、`fromStation`、`toStation`；站点可为中文名或 station code。
- 可选 `trainFilterFlags` (`GDZTKOFS`)、`earliestStartTime/latestStartTime`、`sortFlag={startTime,arriveTime,duration}`、`sortReverse`、`limitedNum`、`format={text,csv,json}`。

归一化 `TicketInfo`：`train_no/start_train_code/start_date/start_time/arrive_date/arrive_time/lishi/from_station/to_station/from_station_telecode/to_station_telecode/prices[]/dw_flag[]`。`Price` 为 `seat_name/short/seat_type_code/num/price/discount`。输出仍包装为 MCP text；JSON mode 是 text 中的 JSON，不提供 `structuredContent`。

### `get-interline-tickets`

在直达参数上增加 `middleStation?`、`showWZ`，默认 `limitedNum=10`；输出 `InterlineInfo`，包含起/中/终站、两程 `ticketList[]`、总时长、等待、同站/同车、日期/时刻。

### `get-train-route-stations`

实际 Zod schema 是 `trainCode/departDate/format`；输出 `RouteStationInfo[]`：station、train code、arrival/start、running time/day label。`docs/principle.md` 仍写需要 from/to station id 和另一个旧 endpoint，与当前源码不一致；应以 tool schema 为准。

### 启动数据流

模块 top-level await 每次启动先从 `www.12306.cn` 下载 station JS，并抓 `leftTicket`/`lcQuery` 的动态 endpoint path，再构建 `STATIONS/CITY_STATIONS/CITY_CODES/NAME_STATIONS`。因此即使只调用本地 station tool，冷启动也依赖网络，没有持久 cache。

- Node engine `>=18`；本机 Node 24。

- `npm run build` = prebuild 清 `build/*` → `tsc` → chmod；`node build/index.js` 默认 stdio，`--port`/`--host` 走 HTTP。
- npm install 输出包含 `ink` peer override、两个 deprecated package 警告；build 输出 `DEP0190`，原因是 `run-script-os` 以 `shell:true` 传 args。当前仍 build 成功，但依赖健康需跟踪。

为不修改 reference clone，本研究从 commit `git archive` 到 `research/evidence/12306-mcp-work/`，在那里安装、build 和启动；npm cache 明确定向 `research/evidence/npm-cache/`。参考 clone `git status --short` 保持空。

## 4. 外部服务、Key、配额与费用

| 服务 | Key | 用途 | 配额/费用 | 无 Key/失败表现 |
|---|---|---|---|---|
| `https://www.12306.cn/index/` | 无 API Key | 启动时发现 station JS | 仓库未声明 quota/费用；公共查询免费 | 下载失败时模块初始化抛错，server 无法启动。 |
| `https://kyfw.12306.cn` | 无 API Key；运行时先取 public cookie | left ticket、interline、train info | 未声明 rate limit；库存/售票规则由 12306 决定 | 返回 `Error: get cookie/tickets...` text；无系统化 retry/backoff。 |
| `https://search.12306.cn` | 无 | train code → train_no | 未声明 quota/费用 | 经停查询返回未查到。 |

不申请、不存用户凭据，不做登录、实名、下单或支付。项目 README 标注学习用途。运行时必须有外网；没有 offline station snapshot/cache fallback。

## 6. 优点、缺点与职责边界

### 优点

- 直达/中转/经停/站码 8 个工具组成最完整的 12306 query MCP 参考，且实际可 build、启动、调用。
- Zod schema 提供日期、时间范围、filter/format 限制；结果把座位、价格、数量/候补和标签归一化。
- stdio 与 HTTP 两种 transport，Node 18+，lockfile 存在。
- 动态抓 endpoint path 与 station list 能适应 12306 前端路径变化的一部分。

### 缺点

- 每次冷启动都联网下载站表/endpoint；无 cache，12306 TLS/页面变化会让整个 MCP 起不来。
- 没有自动化测试；`npm test` 名称误导，实际只是启动 server。
- API parser 依赖 pipe-delimited 列位置与页面正则，schema drift 风险高；无 fixture regression。
- 失败处理多为 plain text 且常把异常 object 输出 stderr；缺 typed MCP error、retry/backoff、rate-limit 分类。
- JSON 仍塞在 text 中；没有 query timestamp、endpoint/source URL、raw response hash 或 fact-level provenance。
- docs 与当前 `get-train-route-stations` schema/endpoint 已不一致；公共 tool 名 `citys` 是稳定 typo。
- `run-script-os` 触发 Node `DEP0190` 安全警告，安装树含 deprecated legacy MCP package。

### 职责边界

负责：公开 12306 station、余票、价格、直达/中转和经停查询。明确不负责：购票/登录/实名/支付、旅程级路线可行性、站外接驳、酒店/航班、HTML、库存保证。

## 7. 可搬走什么、为什么不搬

### 采用其思想

- 采用 station resolution → direct search → bounded interline → route-stops 的工具分层。
- 采用车种/时段/filter/limit，减少 LLM context；保留 seat price/availability 的结构字段。
- 在目标插件中将其作为 provider adapter，外层补 query time、source、health、cache 和 schema fixture。

### 不直接搬代码/配置

- 不直接 vendoring parser；优先以固定 npm/MCP 版本接入并做 contract probe，或选维护更强的 fork 后再裁决。
- 不接受“启动即强联网且无 cache”；目标要有 station snapshot/cache 与 degraded 状态。
- 不沿用 text-only JSON、无 timestamps、无 typed errors 的输出合同。
- 不把 `npm test` 当测试；需要录制脱敏 12306 fixtures 和 parser/tool integration tests。
- 不扩展到交易动作；只输出 12306/官方购买链接和放票提醒。
