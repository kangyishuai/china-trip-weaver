## 1. 定位与触发

`SKILL.md` description 原文：

> 使用 Python 脚本调用 12306 接口，查询车票、车站和列车信息。

明确意图来自正文 tool list：查当前日期、城市/车站 code、站点详情、直达余票、中转余票、指定车次经停。description 没有列“高铁、余票、中转、经停”等常见触发词，也没有“不购票”的负边界；隐式召回质量弱于 `12306-mcp` tool descriptions 和 `search-china-trains`。

可用命令名与 12306-mcp 基本一致，另加 `refresh-cache` 与 `list-tools`：`get-current-date`、4 个 station tool、`get-tickets`、`get-interline-tickets`、`get-train-route-stations`。

## 2. 输入、输出与数据结构

唯一实现文件 `scripts/12306_apis.py`，约 770 行。CLI 参数使用 snake_case：

- station：`--city`、`--citys`、`--station_names`、`--station_telecode`。
- tickets：`--date/--from_station/--to_station`，另有 `train_filter_flags`、0–24 小时过滤、`sort_flag/startTime|arriveTime|duration`、reverse、limit、`text|csv|json`。
- interline：增加 `middle_station/show_wz`，默认 limit 10。
- route：`train_code/depart_date/format`。

内部数据与 MCP 版同源：

- `STATIONS/CITY_STATIONS/CITY_CODES/NAME_STATIONS`。
- ticket normalized dict：train no/code、start/arrive dates/times、duration、from/to names/telecodes、`prices[]`、`dw_flag[]`。
- price：seat name/short/type code、availability `num`、price、discount。
- interline：三站、两程 ticket list、same station/train、wait time、total duration。
- output 全是 stdout string；JSON mode 是 JSON 字符串，没有独立 schema 文件、timestamp 或 source metadata。

它试图把 `lcquery_path` 和 `stations.json` 缓存在 `scripts/` 旁 1 天，以避免 MCP 版每次冷启动全量下载；但当前路径构造写成 `os.path.join(__file__, "..", ...)`，实际 parent 是 `.../12306_apis.py/..`，会触发 `NotADirectoryError`，见实测。

## 3. 脚本与依赖

- README 要求 Python `3.10+`，唯一第三方依赖是 `requests`；无 `requirements.txt`/`pyproject.toml`/lockfile，版本未锁。
- 使用标准库 `argparse/json/zoneinfo` 等；没有安装脚本或 `agents/openai.yaml`。
- HTTP 请求均为裸 `requests.get()`：未设置 timeout、`raise_for_status`、User-Agent、retry/backoff；可能无限等待或把 200 login/error HTML 当正常页面。
- `check_date()` 对 naive `datetime.fromisoformat(date)` 调 `astimezone(Asia/Shanghai)`，其含义依赖宿主本地时区，不是纯粹把输入解释成上海日期。
- 每个 CLI command 都先 `init()`，所以即使 `list-tools/get-current-date` 也需要初始化网络/cache，违反可离线 introspection 的直觉。

## 4. 外部服务、Key、配额与费用

与 `12306-mcp` 相同：`www.12306.cn` 站表、`kyfw.12306.cn` left ticket/interline/train info、`search.12306.cn` train search；不需用户 API Key，仓库未声明 quota 或费用。query 仍需要 public cookie，库存以 12306 实时结果为准。

无 Key 不构成降级问题；真正降级触发是网络/页面/regex 变化。当前实现没有 cache fallback 首包，也没有 typed provider health：失败时打印 `Error: ...` 并 exit 1 或返回错误字符串。

## 5. 测试现状与实测

自动化测试：**无**。仓库只有 4 个 tracked files，没有 tests/CI。README 的 Quick Start 本身是唯一可运行验证。

为不修改只读 reference clone，研究从 commit archive 到 `research/evidence/12306-skill-work/`，按 README 运行：

```bash
python3 scripts/12306_apis.py list-tools
```

同一实测连续 3 次均 exit `1`：

```text
Error: Error: get station name js file failed.
```

系统 `python3` 是 3.9.6，低于要求；为排除该因素，又用已有 Python 3.13.12 + requests 2.32.5 复跑，仍 exit `1` 同错。只读诊断定位到 `get_lc_query_path()`：请求被 12306 重定向到 `otn/resources/login.html`，没有 `lc_search_url`；MCP 版为相同 init 请求加了 `Accept-Language` header，而 Python 版没有。即使这步修好，缓存 parent 也已实证 `NotADirectoryError`。

完整 3 次输出、受支持 Python 复跑与诊断：[`../evidence/12306-skill-list-tools.txt`](../evidence/12306-skill-list-tools.txt)。按“同一实测连败三次换下一项”停止；这是当前 commit 的可复现死路，不据此否定仓库存在。

## 6. 优点、缺点与职责边界

### 优点

- 相比 MCP，Agent 可直接 subprocess 调 CLI，不需要 MCP transport；参数/输出与 12306 领域对齐。
- 设计上增加 1 天 station/path cache，若修复能显著改善冷启动。
- filter/sort/limit 能控制 LLM 上下文，功能面覆盖 direct/interline/route/station。
- 单一 `requests` 依赖、源码体量小，便于审查。

### 缺点

- 当前 commit 连 `list-tools` 都不可运行：缺 header 导致 lcQuery init 重定向；cache 路径也确定错误。
- 无测试、CI、依赖锁、LICENSE、metadata UI；不应作为生产依赖。
- monolithic、许多一行函数/长 dict，维护和 diff 审查困难。
- 无 timeout/retry/status validation，网络可靠性与错误分类弱。
- cache 写在 Skill 源目录，安装到只读/共享 plugin cache 时不合适；应写 `PLUGIN_DATA`/XDG cache。
- 复制了 12306 parser 的脆弱列位置/regex，却没有跟随 MCP 新版 Accept-Language 和动态 ticket path 修复。
- 输出无 query time/source/raw evidence，也没有交易边界。

### 职责边界

负责意图是 12306 查询 CLI；当前 commit 实际被 init 阻塞。完全不处理住宿、航班、POI、行程排程、HTML 或交易。

## 7. 可搬走什么、为什么不搬

### 采用其思想

- “CLI adapter + Skill instructions”是 MCP 不可用时的有效 fallback 形状。
- station/path cache、filter/sort/limit 值得保留，但 cache 应版本化、写 data dir、可离线读取并有 refresh health。

### 不搬

- 当前代码是已实证死路，不直接复制；优先使用可运行的 `12306-mcp`，或等待上游修复并加 fixture tests。
- 不复制 parser/source without license。
- 不沿用 `__file__/..`、裸 `requests.get`、全命令强制 init、text-only output。
- 不让 train Skill 自己成为宽触发主编排器；它应是窄 provider Skill，并明确只查不购。
