# v2 旅程剖面：可见能力映射（集成候选）

本表按 [v1 renderer 合同](../07-renderer.md) 与实际 Trip/Journey 渲染代码核对。v2 页面首层给出旅客最常比较的时间关系；“完整行程与来源记录”中的内容是 **实际可见的 HTML**，由现有 v1 函数渲染，点击 summary 展开即可读，并非仅藏在 `<script>` 的 JSON。所有链接仍是用户主动打开的安全 HTTPS 来源。没有浏览器验收前，下表证明源码落点与静态输出，不证明交互或视觉质量。

C03 后折叠区不再重复显示完整 v1 页头与大型真实性横幅；独有元数据和状态在“记录范围与真实性”摘要中可读，原导航、全部事实 section 与含条件署名的 footer 仍逐字复用。

截图退修后的 v2 默认顺序是紧凑路线/日期与首要交通核验→当天时段/住处/预算状态→全程同刻度时间图→所选日的分组原始核验依据→完整记录。住宿/预算的次要决定与各城市停留日期仍可由原生 `details` 打开；默认核验主题以中英界面文案表达，所有 unknown 的原始 ID、field、reason、claim 状态和来源在分组依据中逐条可读。预算不完整时主值是待核验状态，已知可比金额是次级口径；`known_cost_cny` 没有改写。图带继续用相同分钟轴计算，只将显示时长换成小时/分钟并补齐用餐、休息和留白的图例。此段是源码合同，未替代实际手机/桌面视觉验收。

展示层判断总费用是否完整要看账本 `total_range_cny.minimum/maximum`，不能把 `status=unbudgeted`（未设预算上限）当作总价已知；`known_cost_cny=0` 也不能证明没有真实的0元可比项。试算只替换移动交通腿的原/假设时刻，其他时段的时间保持原样。交通服务编号的核验主题对铁路、渡轮等模式使用中性表述；更具体的服务类型留在来源事实中。

| 旧页可见能力 | v2 可见落点 | 保留的源事实/限制 |
|---|---|---|
| Trip 与 Journey、分组出发及跨段衔接 | 顶部完整城市顺序与日期；完整记录中的请求、路线、分段、衔接、组别及 meeting anchor | 不把组别起点合并为一个人；原组别/人数由旧记录逐项列出。 |
| 已选、备选、未采用、状态未知 | 时间带仅画 `scheduled` 且非 `free`；焦点当天的非生效项单独折叠；完整记录保留所有候选与原因 | 备选不冒充当前占用。 |
| 交通、车站、余票、锁定与来源 | 焦点时段和首条交通优先决定；完整交通摘要/Journey 跨城与清单记录显示车站、座位状态、来源、锁定 | 时间试探只对可移动草案时段工作，不推断真实车次与票价。 |
| 住宿、过夜锁定、价格与计价单位 | 焦点当晚住处及明确计价性质/单位；完整住宿摘要与各天/段落的锁定、候选和 deep link | 价格未知仍未知，参考价不写成成交总额；完整记录逐项列出选择。 |
| 预算与币种、已知成本/未知范围 | 顶部预算边界与焦点已知可比较金额；完整记录的 ledger/范围与各项价型 | 缺价不作为零；若合法旧 Trip 没有 ledger，则显示金额未知。 |
| 每天天气、餐饮参考 | 完整记录的逐日天气与 slot 餐饮块；原有无预报/暂无餐饮状态继续可读 | v2 时间带不把天气/餐饮伪装成已证实时段。 |
| 位置、坐标未知、非道路示意 | 完整位置概览及其说明/官方深链 | 无坐标时明确“位置未核验”，不画默认点。 |
| 核验截止、风险、冲突 | Journey 完整清单、优先事项、风险及段缝；焦点相关未知直接可见 | deadline_kind 和原 claim 状态继续保留。 |
| 全部 unknown、claim、provider 降级 | 焦点的相关未知；完整记录中的全部未知、证据、来源和数据源状态 | 完整原 JSON 另以内嵌 inert script 保留，便于后续修订；不以它代替可读记录。 |

实现入口：`render/html.py`、`render/journey_html.py` 按版本调用 `profile_html.py`；纯派生时间关系在 `profile_model.py`；固定 CSS/JS 在 `assets/profile.*`；`profile_validate.py` 与原 v1 校验器分派。架构决定见 [ADR-0023](../adr/0023-versioned-journey-profile.md)。旧页行为仍由 [ADR-0006](../adr/0006-single-deterministic-renderer.md) 约束。新增资产不影响 Python 3.9 标准库运行时。
